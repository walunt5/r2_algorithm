R2 视觉伺服测试命令行速查
==========================

适用范围
--------
这些命令用于通过 ROS2 命令行测试视觉桥、端头目标筛选、视觉伺服 action server、以及 BT 视觉伺服测试 XML。

默认前提：

  cd ~/techx_R2_algorithm/r2_algorithm
  source /opt/ros/humble/setup.bash
  source install/setup.bash


一、构建相关包
==============

构建视觉伺服、BT 接入、视觉桥相关包：

  colcon build --symlink-install --packages-select r2_vision_servo_interfaces r2_vision_servo r2_bt_nodes r2_bt_executor r2_bt_bringup techx_vision_bridge

构建后重新 source：

  source install/setup.bash

确认 action 接口存在：

  ros2 interface show r2_vision_servo_interfaces/action/VisionServo

确认视觉伺服可执行文件存在：

  ros2 pkg executables r2_vision_servo


二、启动视觉桥和 mock Jetson
===========================

终端 1：启动视觉桥。

  ros2 launch techx_vision_bridge vision_bridge.launch.py

终端 2：没有真实 Jetson 发 UDP 时，启动 mock sender。

  ros2 run techx_vision_bridge mock_jetson_sender.py --mode mixed --ip 127.0.0.1

如果真实 Jetson 已经在发 UDP，就不要再启动 mock sender，避免数据混在一起。

- 这里直接发布 /techx/vision/request，不使用 vision_request_demo.py。

四、观察视觉筛选结果
====================

持续观察 selected：

  ros2 topic echo /techx/vision/selected

只看一帧 selected：

  ros2 topic echo --once /techx/vision/selected

成功匹配目标时重点看这些字段：

  request_seq: 1
  status: 1
  has_match: true
  target:
    class_id: ...
    robot_x: ...
    robot_y: ...
    robot_z: ...

常见现象：
- status=1 且 has_match=true：视觉桥已经选中目标。
- class_id 等于你请求的值：当前选中的目标正确。
- robot_x/robot_y/robot_z：视觉伺服使用的底盘对准坐标。
- status=3 或 has_match=false：没有匹配目标，检查 class_id、target_type、zone_id、置信度和 Jetson 数据。


五、启动视觉伺服 dry-run
=======================

终端 3：启动视觉伺服 action server。
默认读取 r2_vision_servo/config/vision_servo.yaml，其中 enable_cmd_vel=false。

  ros2 launch r2_vision_servo vision_servo.launch.py

显式指定配置文件：

  ros2 launch r2_vision_servo vision_servo.launch.py config_file:=install/r2_vision_servo/share/r2_vision_servo/config/vision_servo.yaml

临时覆盖 YAML 中的单个参数：

  ros2 launch r2_vision_servo vision_servo.launch.py max_vx:=0.04 max_vy:=0.04 max_wz:=0.15

看到类似下面日志表示启动成功：

  vision_servo_action_server ready action=/r2_chassis/vision_servo request=/techx/vision/request selected=/techx/vision/selected cmd_vel=/cmd_vel mode=DRY-RUN

如果没有真实 Odin/定位 TF，只做桌面 dry-run，可以临时发布静态 TF。
有真实 Odin/定位时不要发这条静态 TF。

  ros2 run tf2_ros static_transform_publisher 0 0 0 0 0 0 map chassis_base_link


六、直接请求视觉伺服 action 对准所有目标
======================================

说明：
- 这个 action 会自己向 /techx/vision/request 发布目标请求。
- 默认 dry-run 下只计算速度并反馈 cmd_vx/cmd_vy/cmd_wz，不发布非零 /cmd_vel。
- 武器头使用 align_strategy=3，即 yaw_then_y_then_x。
- KFS 和二维码使用 align_strategy=4，即 yaw_gate_xy_parallel。
- yaw_mode=1 表示启动瞬间锁定当前 yaw 并保持。
- action 内部使用 selected.target.robot_x/robot_y/robot_z 做底盘对准。
- 二维码也可以请求，但视觉伺服仍需要 selected.target.valid_robot_xyz=true。

八、dry-run 结果解释
===================

dry-run 是默认安全模式：
- 会筛选视觉目标。
- 会读取 TF yaw。
- 会计算 error_x/error_y/yaw_error_rad。
- 会计算 cmd_vx/cmd_vy/cmd_wz。
- 不会发布非零 /cmd_vel 驱动车。

因此如果视觉目标坐标不变，误差不会真的变小，action 或 BT 最后 timeout/FAILURE 是正常现象。

例如：

  err=(-0.600, 0.000, 0.000) cmd=(-0.060, 0.000, 0.000) stable=0/5

含义是：
- 当前 X 方向还差 -0.600m。
- 视觉伺服计算出 vx=-0.060m/s。
- 因为 dry-run 不动车，stable 一直是 0/5，最后会超时。


九、实车开启 /cmd_vel 输出
=========================

重要：
- 只有确认视觉坐标、TF、速度方向、急停和现场安全后再开启。
- 开启后视觉伺服会向 /cmd_vel 发布非零速度。

单独启动视觉伺服并允许发 /cmd_vel：

  ros2 launch r2_vision_servo vision_servo.launch.py enable_cmd_vel:=true

通过真实任务 bringup 同时启动视觉伺服，并允许发 /cmd_vel：

  ros2 launch r2_bt_bringup r2_task_real_bringup.launch.py launch_vision_servo:=true vision_servo_enable_cmd_vel:=true

通过 mock bringup 启动视觉伺服但保持 dry-run：

  ros2 launch r2_bt_bringup r2_task_mock_bringup.launch.py launch_vision_servo:=true

紧急补发停止命令：

  ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}"
